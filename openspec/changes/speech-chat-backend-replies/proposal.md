## Why

The speech chat modal already records audio and posts to `/api/speech/chat`, but assistant replies are generated by a rotating stub in the Next.js route—not a real backend service. Users need their recording visible as the chat input (audio bubble) and assistant messages that appear only after the server finishes processing and returns a response, with no client-side or canned automated replies.

## What Changes

- Show the captured recording in the user chat bubble as soon as the recording ends (before and while the upload runs), with clear sending/sent/error states.
- Keep existing chat elements: thread, assistant text bubbles, read-aloud toggle, multi-turn flow, modal shell, FAB entry.
- Remove stub/canned assistant responses from `/api/speech/chat`; the route SHALL delegate to a configurable backend speech service and return only that service’s reply (or a proper error).
- Frontend SHALL `await` the chat API and render the assistant bubble only from the HTTP response—no optimistic assistant text, no local placeholder replies, no `speechSynthesis` until server text is received.
- Add a visible “waiting for assistant” state in the thread while the request is in flight (after the user audio bubble is shown).
- Return HTTP 503 (or equivalent) when the speech service is not configured, so the UI can show failure instead of fake success.

## Capabilities

### New Capabilities

- _(none)_

### Modified Capabilities

- `speech-chat-ui`: Immediate audio input bubble, in-thread loading while awaiting server, assistant bubble only after successful response.
- `speech-chat-api`: Remove stub replies; service-backed responses only; documented request/response contract for the speech service proxy.

## Impact

- `app/components/speech/SpeechChatProvider.tsx` — send flow, loading assistant state, no local reply generation.
- `app/components/speech/SpeechChatModal.tsx` — audio bubble UX, thinking/loading indicator.
- `app/app/api/speech/chat/route.ts` — remove `STUB_REPLIES`; proxy to `SPEECH_SERVICE_URL` (or fail clearly).
- `app/lib/speech/types.ts` — optional loading message type or status flags.
- Environment: `SPEECH_SERVICE_URL` (and optional timeout) for service integration.
